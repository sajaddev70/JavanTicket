## ۱. سامانه چیست؟

«جوان تیکت» یک سامانه کامل بلیت‌فروشی است با سه کاربر اصلی:

| کاربر | کار او در سامانه |
|---|---|
| **خریدار (کاربر سایت)** | رویدادها را بر اساس شهر، دسته‌بندی و زمان پیدا می‌کند، سانس را انتخاب می‌کند، صندلی را از روی نقشه سالن برمی‌دارد (یا تعداد بلیت ورود عمومی را انتخاب می‌کند)، پرداخت آنلاین انجام می‌دهد و بلیت الکترونیکی با کد QR می‌گیرد. |
| **مدیران و کارمندان (پنل مدیریت)** | رویداد، سالن، نقشه صندلی، سانس و قیمت تعریف می‌کنند؛ محتوای کل سایت (بنر، منو، صفحات، متن‌ها) را می‌نویسند؛ فروش، رزرو گروهی مدارس، پیش‌فاکتور، تسویه با برگزارکننده، CRM و گزارش‌ها را مدیریت می‌کنند. |
| **کنترل‌گر گیت** | در ورودی سالن، کد QR بلیت را با دوربین یا اسکنر می‌خواند و ورود را ثبت می‌کند. |

ویژگی‌های کلیدی:

- **ورود با پیامک (OTP)** — بدون رمز عبور، هم برای خریدار و هم برای مدیر.
- **نقشه صندلی واقعی** با چند بخش، ردیف‌بندی، قوس، سطح قیمت (VIP، طلایی، نقره‌ای، معمولی) و صندلی‌های غیرفعال.
- **نگهداری موقت صندلی** — صندلی انتخاب‌شده چند دقیقه (پیش‌فرض ۱۰ دقیقه) برای خریدار قفل می‌شود.
- **کد تخفیف، هزینه خدمات، استرداد** و صدور خودکار بلیت پس از پرداخت.
- **فروش سازمانی**: مدارس و سازمان‌ها، رزرو گروهی، پیش‌فاکتور قابل چاپ.
- **امور مالی**: دفتر تراکنش‌ها، تسویه با برگزارکنندگان، گزارش‌های تحلیلی با خروجی CSV.
- **نقش و دسترسی** دقیق برای هر کارمند و **لاگ کامل فعالیت‌ها**.
- **همه صفحات راست‌چین، تم تیره و روشن، ریسپانسیو (موبایل تا دسکتاپ) و قابل نصب (PWA)**.

## ۲. معماری و اجزای پروژه

```
JavanTicket/
├── src/                  ← بک‌اند: Kotlin + Spring Boot 4 (پکیج com.devs.nisha)
│   └── main/resources/
│       ├── db/migration/ ← ساختار پایگاه داده (Flyway، فایل‌های V1 تا V10)
│       └── static/media/ ← تصاویر پیش‌فرض (پوستر، سالن، شهر، آیکون‌ها)
├── frontend/
│   ├── user/             ← سایت کاربر (Next.js 16، پورت 3003)
│   └── admin/            ← پنل مدیریت (Next.js 16، پورت 3002، آدرس /admin)
├── android/              ← اپلیکیشن‌های اندروید (user و admin)
├── docker-compose.yml    ← اجرای کامل: db → backend → admin → user
├── Dockerfile            ← ایمیج بک‌اند
└── docs/                 ← مستندات (همین کتابچه)
```

| جزء | فناوری | پورت پیش‌فرض | آدرس |
|---|---|---|---|
| پایگاه داده | PostgreSQL 17 | 5432 | — |
| بک‌اند (API) | Kotlin، Spring Boot 4، JWT، Flyway | 8081 | `http://SERVER:8081/api/v1` — مستندات API: `/swagger-ui.html` |
| پنل مدیریت | Next.js 16، React 19، Tailwind 4، React Query | 3002 | `http://SERVER:3002/admin` |
| سایت کاربر | Next.js 16، React 19، Tailwind 4، React Query | 3003 | `http://SERVER:3003` |

جریان داده: **پنل مدیریت ← API ← پایگاه داده ← API ← سایت کاربر**. هیچ متن، تصویر یا لینکی در کد سایت کاربر ثابت نوشته نشده؛ هر چه کاربر می‌بیند از پایگاه داده می‌آید و از پنل مدیریت قابل تغییر است.

## ۳. راه‌اندازی

### ۳-۱. روی سرور با Docker (پیشنهادی)

پیش‌نیاز: Docker و Docker Compose، و JDK 17 برای ساخت فایل jar.

```bash
# ۱) ساخت فایل اجرایی بک‌اند
./gradlew clean bootJar

# ۲) ساخت فایل تنظیمات
cp .env.example .env
#    در .env حتماً این‌ها را پر کنید:
#    JWT_SECRET=<یک رشته تصادفی بلند>     (مثلاً خروجی: openssl rand -hex 32)
#    PUBLIC_API_URL=http://IP_SERVER:8081/api/v1
#    PUBLIC_USER_SITE_URL=http://IP_SERVER:3003

# ۳) اجرا
docker compose up -d --build

# ۴) مشاهده لاگ بک‌اند (پر شدن داده نمایشی را اینجا می‌بینید)
docker compose logs -f backend
```

ترتیب بالا آمدن سرویس‌ها خودکار است: `db` ← `backend` ← `admin` ← `user`؛ هر سرویس صبر می‌کند تا قبلی سالم شود.

> **مهم:** `PUBLIC_API_URL` و `PUBLIC_USER_SITE_URL` هنگام **ساخت** فرانت‌ها داخل آن‌ها قرار می‌گیرند. اگر IP یا دامنه را عوض کردید، دوباره `docker compose up -d --build` بزنید.

### ۳-۲. اجرای محلی برای توسعه

```bash
# بک‌اند (PostgreSQL محلی با کاربر postgres / رمز 1234؛ اگر دیتابیس youth_event نباشد خودش ساخته می‌شود)
./gradlew bootRun

# پنل مدیریت
cd frontend/admin && npm install && npm run dev     # http://localhost:3002/admin

# سایت کاربر
cd frontend/user && npm install && npm run dev      # http://localhost:3003
```

بدون کلید پیامک، کد ورود همیشه **`1111`** است (فقط در لاگ بک‌اند نوشته می‌شود).

## ۴. داده نمایشی (دمو)

هدف: وقتی سامانه برای اولین بار بالا می‌آید، **هیچ صفحه‌ای خالی نباشد** و هر کسی دمو را باز کند، یک سامانه زنده و پر ببیند.

### چه چیزهایی پر می‌شود؟

کلاس `DemoDataSeeder` (در `src/main/kotlin/com/devs/nisha/config/DemoDataSeeder.kt`) هنگام بالا آمدن بک‌اند این داده‌ها را می‌سازد؛ تاریخ‌ها نسبت به **امروز** ساخته می‌شوند، پس دمو همیشه به‌روز است:

| بخش | داده |
|---|---|
| شهرها | ۶ شهر (تهران، مشهد، اصفهان، شیراز، تبریز، کرج) با تصویر، مختصات نقشه و وضعیت |
| سالن‌ها | ۱۴ سالن؛ ۷ سالن با **نقشه صندلی حدود ۵۰۰ صندلی** در ۱۰ بخش و ۴ سطح قیمت |
| دسته‌بندی‌ها | ۹ دسته (کنسرت، همایش، تئاتر، کارگاه، ورزشی، نمایشگاه، کودک، کسب‌وکار، سایر) با آیکون و رنگ |
| رویدادها | ۵۲ رویداد (منتشرشده، پیش‌نویس، لغوشده) با پوستر، توضیح، برگزارکننده |
| سانس‌ها | ۶۸ سانس از روزهای گذشته تا ۴۳ روز آینده، با قیمت هر سطح صندلی |
| صفحه کامل رویداد | آمار، محورها، سخنرانان، گالری و سوالات متداول (نمونه: `iran-tech-expo`) |
| مشتریان | ۱۲۰۰ کاربر |
| سفارش و بلیت | حدود ۶۰۰۰ سفارش در ۳۷ روز گذشته (روند فروش رو به رشد)، حدود ۱۵۰۰۰ بلیت، استردادها، سفارش‌های لغوشده |
| پرداخت‌ها | یک تراکنش درگاه برای هر سفارش (موفق، ناموفق، باز) |
| صندلی‌ها | صندلی‌های فروخته‌شده و مسدود روی نقشه هر سانس |
| گیت | سوابق اسکن ورود (مجاز، تکراری، نامعتبر) |
| فروش سازمانی | ۱۴ مدرسه/سازمان، حدود ۲۴۰ رزرو گروهی، حدود ۵۰ پیش‌فاکتور، تسویه با برگزارکنندگان |
| CRM | ۳۶ تماس و پیگیری با مشتریان و سازمان‌ها |
| کارمندان | ۵ کارمند با نقش‌های مختلف + لاگ دو هفته فعالیت |
| محتوای سایت | تنظیمات سایت، سربرگ‌ها، ۴ بنر اسلایدر، مزایا، بخش‌های صفحه اصلی، ۶ صفحه محتوایی، منوی بالا و فوتر، کدهای تخفیف، خبرنامه، هشدارها |
| **مشتری نمایشی** | حساب `09121234567` با بلیت صندلی‌دار VIP، بلیت ورود عمومی، بلیت استفاده‌شده، سفارش مسترد، سفارش رهاشده و ۶ رویداد مورد علاقه |

### چه زمانی اجرا می‌شود؟ (ایمن برای سرور واقعی)

| وضعیت پایگاه داده | رفتار |
|---|---|
| کاملاً خالی (نصب تازه) | داده نمایشی پر می‌شود ✅ |
| قبلاً با همین نسخه دمو پر شده | کاری نمی‌کند |
| قبلاً با نسخه قدیمی‌تر دمو پر شده | دمو پاک و با نسخه جدید دوباره پر می‌شود (`DEMO_SEED_RESEED=true`) |
| **دارای داده واقعی** (رویداد، سفارش یا مشتری که دمو نساخته) | **هرگز دست نمی‌زند** ✅ |

در هیچ حالتی **حساب‌های مدیر، نقش‌ها و منوی پنل** پاک نمی‌شوند.

### متغیرهای کنترل (در `.env`)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `DEMO_SEED_ENABLED` | `true` | خاموش کردن کامل داده نمایشی با `false` |
| `DEMO_SEED_RESEED` | `true` | با آمدن نسخه جدید دمو، داده دموی قبلی جایگزین شود |
| `DEMO_SEED_FORCE` | `false` | **یک‌بار** `true` کنید تا هر چه هست (به جز مدیران) با دمو جایگزین شود؛ بعد از بالا آمدن حتماً به `false` برگردانید |

مثال — پر کردن دمو روی سروری که قبلاً چند داده آزمایشی دستی دارد:

```bash
# در .env
DEMO_SEED_FORCE=true
docker compose up -d backend          # صبر تا در لاگ ببینید: Sample data loaded
# سپس دوباره:
DEMO_SEED_FORCE=false
docker compose up -d backend
```

> **برای راه‌اندازی واقعی (تولید):** قبل از اولین اجرا `DEMO_SEED_ENABLED=false` بگذارید تا سامانه خالی تحویل داده شود.

## ۵. ورود به سامانه و حساب‌های آماده

ورود همه‌جا با **شماره موبایل + کد پیامکی** است. تا وقتی کلید کاوه‌نگار (`KAVENEGAR_API_KEY`) تنظیم نشده، پیامکی ارسال نمی‌شود و **کد همیشه `1111`** است.

| حساب | موبایل | کجا وارد شود | دسترسی |
|---|---|---|---|
| مدیر ارشد | `09101414285` | پنل مدیریت | همه بخش‌ها (SUPER_ADMIN) — همیشه وجود دارد |
| مدیر رویدادها | `09121110001` | پنل مدیریت | رویداد، سانس، سالن، شهر، نقشه صندلی، تقویم |
| مدیر مالی | `09121110002` | پنل مدیریت | مالی، تسویه، پیش‌فاکتور، سفارش، تخفیف، گزارش |
| مدیر فروش | `09121110003` | پنل مدیریت | سفارش، رزرو گروهی، مدارس، پیش‌فاکتور، CRM، تخفیف |
| کنترل‌گر گیت | `09121110004` | پنل مدیریت | فقط کنترل گیت |
| مدیر محتوا | `09121110005` | پنل مدیریت | بنر، صفحات، منو، سربرگ‌ها، خبرنامه، هشدارها |
| مشتری نمایشی | `09121234567` | سایت کاربر | بلیت‌ها، سفارش‌ها، علاقه‌مندی‌ها |

> هر شماره دیگری هم در سایت کاربر وارد شود، حساب خریدار برایش ساخته می‌شود. در پنل مدیریت فقط شماره‌هایی وارد می‌شوند که مدیر ارشد به آن‌ها نقش داده باشد.

## ۶. قانون طلایی: همه چیز از پنل مدیریت

در این سامانه **هیچ محتوای ثابتی** وجود ندارد. نام سایت، لوگو، شماره تماس، متن فوتر، بنرها، منوها، صفحات «درباره ما» و «قوانین»، سربرگ صفحات، مزایای خرید، ردیف‌های صفحه اصلی، رویدادها و قیمت‌ها همه در پایگاه داده‌اند و از پنل مدیریت ویرایش می‌شوند. هر تغییری بلافاصله (یا با یک رفرش) در سایت کاربر دیده می‌شود.

تصاویر را می‌توانید در هر فرم با دکمه **«بارگذاری تصویر»** آپلود کنید؛ فایل روی سرور (پوشه `uploads`) ذخیره و آدرسش در فرم قرار می‌گیرد.

## ۷. راهنمای قدم‌به‌قدم: از صفر تا فروش اولین بلیت

این مسیر را برای ثبت یک رویداد جدید دنبال کنید (در دمو همه این مراحل قبلاً انجام شده و می‌توانید نمونه‌ها را ببینید).

### قدم ۱ — تنظیمات پایه سایت
**پنل ← تنظیمات و زیرساخت ← تنظیمات سامانه**
نام سایت، نام کوتاه، شعار، توضیح موتورهای جستجو، لوگوی روشن و تیره، تلفن، ایمیل، نشانی، شبکه‌های اجتماعی، متن خبرنامه، متن فوتر و **درصد هزینه خدمات** را وارد کنید.
← در سایت: هدر، فوتر، عنوان تب مرورگر، آیکون نصب PWA، صفحه پرداخت (هزینه خدمات).

### قدم ۲ — شهر
**پنل ← مدیریت موقعیت‌ها ← شهرها ← «افزودن شهر»**
نام، استان، مدیر شهر، تصویر، مختصات (برای نقشه داشبورد) و وضعیت (فعال / در برنامه / غیرفعال).
← در سایت: انتخاب شهر در هدر، بخش «رویدادها در شهرهای مختلف» صفحه اصلی، فیلتر شهر.

### قدم ۳ — سالن
**پنل ← مدیریت موقعیت‌ها ← سالن‌ها ← «افزودن سالن»**
شهر، نام سالن، نام مجموعه، نشانی، نوع، ظرفیت، تعداد گیت، تصویر و وضعیت.

### قدم ۴ — نقشه صندلی (اختیاری؛ برای فروش صندلی‌دار)
**پنل ← مدیریت موقعیت‌ها ← نقشه صندلی‌ها**
1. سالن را انتخاب کنید.
2. تب **«مدیریت بخش‌ها»**: بخش‌ها را بسازید (نام، ردیف شروع، تعداد ردیف، صندلی در هر ردیف، موقعیت، قوس، سطح قیمت). صندلی‌ها خودکار ساخته می‌شوند.
3. تب **«نقشه صندلی‌ها»**: با «انتخاب دستی صندلی» صندلی‌هایی را که نباید فروخته شوند (جای دوربین، فنی) **غیرفعال** کنید.
4. تب **«تنظیمات سالن»**: ظرفیت و مشخصات.

> سالن بدون نقشه صندلی = فروش **ورود عمومی** (خریدار فقط تعداد بلیت را انتخاب می‌کند).

### قدم ۵ — دسته‌بندی
**پنل ← مدیریت رویدادها ← دسته‌بندی‌ها**
نام، نامک (`slug`، انگلیسی)، شعار، آیکون، تصویر کاور، رنگ و ترتیب.
← در سایت: نوار دسته‌بندی صفحه اصلی و فیلتر صفحه رویدادها.

### قدم ۶ — رویداد
**پنل ← مدیریت رویدادها ← رویدادها ← «افزودن رویداد»**

| فیلد | توضیح |
|---|---|
| عنوان، زیرعنوان | در کارت و صفحه رویداد |
| **نامک (آدرس صفحه)** | بخش آخر آدرس، فقط انگلیسی و بدون فاصله؛ مثلاً `hamid-hirad-concert` ← `/events/hamid-hirad-concert` |
| وضعیت | **منتشرشده** (در سایت دیده می‌شود) / پیش‌نویس (پنهان) / لغوشده (صفحه با برچسب لغو) |
| دسته‌بندی، شهر، سالن، برگزارکننده | |
| شروع قیمت | «قیمت از ...» روی کارت |
| تاریخ شروع/پایان | برای رویدادهای چندروزه |
| پوستر | تصویر کارت و سربرگ صفحه رویداد |
| نمایش در «رویدادهای پیشنهادی» / رویداد محبوب | ورود به ردیف‌های صفحه اصلی |
| درباره رویداد، نکته مهم | متن صفحه رویداد |

بعد از ذخیره، از منوی «⋯» هر رویداد:
- **سانس‌ها و قیمت‌ها** — قدم بعد.
- **محتوای صفحه رویداد** — آمار، محورها، سخنرانان، گالری و سوالات متداول.
- **مشاهده در سایت** — صفحه رویداد در سایت کاربر را باز می‌کند.

### قدم ۷ — سانس و قیمت
**پنل ← رویدادها ← ⋯ ← سانس‌ها و قیمت‌ها** (یا **پنل ← سانس‌ها ← «افزودن سانس»**)
عنوان اختیاری (مثلاً «روز اول: افتتاحیه»)، سالن، وضعیت (فعال = قابل فروش)، زمان شروع و پایان، ظرفیت و قیمت پایه.
برای سالن صندلی‌دار از منوی سانس **«قیمت هر نوع صندلی»** را بزنید و قیمت VIP / طلایی / نقره‌ای / معمولی را وارد کنید.

### قدم ۸ — (اختیاری) کد تخفیف
**پنل ← فروش و سفارشات ← تخفیف و کد معرف**
کد، عنوان، نوع (درصدی یا مبلغ ثابت)، مقدار، حداکثر دفعات استفاده و بازه اعتبار.

### قدم ۹ — نمایش در صفحه اصلی
- **بنرهای صفحه اصلی**: اسلاید جدید با انتخاب **رویداد مرتبط** (لینک خودکار به صفحه رویداد).
- **بخش‌های صفحه اصلی**: ردیف‌هایی مثل «رویدادهای پیشنهادی»، «رویدادهای این هفته»، «محبوب‌ترین‌ها»، «جدیدترین‌ها» یا یک دسته خاص.

### قدم ۱۰ — خرید در سایت کاربر
1. کاربر رویداد را در صفحه اصلی یا `/events` پیدا می‌کند.
2. در صفحه رویداد، سانس را انتخاب و **«خرید بلیت»** را می‌زند.
3. سالن صندلی‌دار ← نقشه صندلی (`/sessions/{id}/seats`)؛ ورود عمومی ← انتخاب تعداد.
4. ورود با موبایل و کد (اگر وارد نشده باشد).
5. صفحه **تکمیل خرید** (`/checkout`): مشخصات خریدار و کد تخفیف؛ تایمر نگهداری صندلی نمایش داده می‌شود.
6. صفحه **پرداخت** (`/payment`): انتخاب درگاه و انتقال به بانک.
7. بازگشت از بانک ← **نتیجه پرداخت** و صدور فوری بلیت‌ها.
8. بلیت‌ها در **«بلیت‌های من»** با کد QR، قابل ارسال پیامکی، اشتراک‌گذاری و افزودن به تقویم.

### قدم ۱۱ — روز رویداد: کنترل گیت
**پنل ← فروش و سفارشات ← کنترل گیت**
سانس را انتخاب کنید، نام گیت را بنویسید و کد QR بلیت را با دوربین (دکمه 📷، روی Chrome اندروید) یا اسکنر دستی بخوانید. نتیجه: **ورود مجاز** / **استفاده‌شده** (بلیت قبلاً اسکن شده) / **نامعتبر**.

### قدم ۱۲ — بعد از رویداد
- **گزارش‌ها**: فروش روزانه، به تفکیک شهر و دسته، پرفروش‌ترین رویدادها، ساعات اوج خرید، اشغال سالن‌ها (همه با خروجی CSV).
- **تسویه حساب‌ها**: محاسبه سهم برگزارکننده (فروش ناخالص − کارمزد) و ثبت پرداخت.

## ۹. راهنمای سایت کاربر

آدرس: `http://SERVER:3003`

| صفحه | آدرس | توضیح |
|---|---|---|
| صفحه اصلی | `/` | اسلایدر (سربرگ + بنرها)، دسته‌بندی‌ها، ردیف‌های رویداد، شهرها، مزایا، بنر دعوت |

| انتخاب صندلی | `/sessions/{id}/seats` | نقشه با بزرگ‌نمایی (دکمه‌ها، دو انگشت یا چرخ ماوس)، قیمت هر سطح، سبد پایین صفحه |

| تکمیل خرید | `/checkout` | مشخصات خریدار، کد تخفیف، خلاصه سفارش، تایمر |
| پرداخت | `/payment`، `/payment/result` | انتخاب درگاه، نتیجه پرداخت و بلیت‌ها |
| بلیت‌های من | `/tickets`، `/tickets/{id}` | آینده / گذشته / لغوشده؛ QR، ارسال پیامک، تقویم |
| سفارش‌های من | `/orders`، `/orders/{شماره}` | همه سفارش‌ها؛ ادامه پرداخت سفارش‌های باز |
| علاقه‌مندی‌ها | `/favorites` | رویدادهای ذخیره‌شده با ♥ |
| حساب کاربری | `/profile` | نام، ایمیل، شهر |

روی موبایل یک **نوار پایین** (خانه، رویدادها، بلیت‌های من، حساب من) هست که در صفحاتی که دکمه پرداخت ثابت دارند (انتخاب صندلی، پرداخت، صفحه رویداد) پنهان می‌شود.

**تجربه دمو برای مشتری:** با `09121234567` و کد `1111` وارد شوید: ۶ بلیت آینده (دو صندلی VIP ردیف الف در «همایش ملی نوآوری در کسب‌وکار»، سه بلیت «کنسرت بزرگ حمید هیراد»، یک بلیت نمایشگاه فناوری)، بلیت‌های استفاده‌شده، سفارش مسترد و علاقه‌مندی‌ها را می‌بینید.

## ۱۰. نقشه «کجا ثبت کنم ← کجا دیده می‌شود»

| می‌خواهم ... را تغییر دهم | در پنل | در سایت دیده می‌شود |
|---|---|---|
| نام سایت، لوگو، تلفن، نشانی، شبکه‌های اجتماعی | تنظیمات سامانه | هدر، فوتر، عنوان صفحات |
| اسلاید اول صفحه اصلی | سربرگ‌ها ← `HOME_HERO` | بالای صفحه اصلی |
| اسلایدهای بعدی | بنرهای صفحه اصلی | اسلایدر صفحه اصلی |
| بنر «همین حالا ثبت‌نام کنید» | سربرگ‌ها ← `HOME_CTA` | پایین صفحه اصلی |
| سربرگ صفحه رویدادها | سربرگ‌ها ← `EVENTS_HERO` | `/events` |
| ردیف‌های رویداد صفحه اصلی | بخش‌های صفحه اصلی | صفحه اصلی |
| یک رویداد در «پیشنهادی‌ها» باشد | رویدادها ← کلید «نمایش در رویدادهای پیشنهادی» | ردیف پیشنهادی |
| آیتم‌های منوی بالا | منوهای سایت ← گروه HEADER | هدر |
| ستون‌های فوتر | منوهای سایت ← گروه‌های FOOTER | فوتر |
| متن «درباره ما» یا «قوانین» | صفحات محتوایی | `/about`، `/terms` |
| نوار مزایای خرید | مزایای خرید | صفحه اصلی، صفحه ورود |
| شهرهای قابل انتخاب در هدر | شهرها (وضعیت فعال) | انتخاب شهر هدر، بخش شهرها |
| آیکون و رنگ دسته‌ها | دسته‌بندی‌ها | نوار دسته‌ها، برچسب کارت‌ها |
| قیمت یک صندلی VIP | سانس‌ها ← قیمت هر نوع صندلی | نقشه صندلی |
| نکات خرید و پرداخت | سربرگ‌ها ← `CHECKOUT_NOTICE`، `PAYMENT_NOTICE` | تکمیل خرید، پرداخت |
| راهنمای ورود به سالن | سربرگ‌ها ← `TICKET_GUIDE` | صفحه بلیت |
| کارمزد هر سفارش | تنظیمات سامانه ← هزینه خدمات | خلاصه سفارش |

| `CONTENT_MANAGER` — مدیر محتوا | داشبورد، بنرها، بخش‌های صفحه اصلی، مزایا، منوها، صفحات، سربرگ‌ها، خبرنامه، هشدارها |
| `GATE_OPERATOR` — کنترل‌گر گیت | فقط کنترل گیت |

**افزودن کارمند جدید:** پنل ← کاربران و مدیران ← کاربر را پیدا یا اضافه کنید ← نوع «مدیر» و نقش را انتخاب کنید. از این لحظه با موبایل خودش وارد پنل می‌شود و فقط بخش‌های نقشش را می‌بیند. حساب `09101414285` در هر بار بالا آمدن بک‌اند به‌طور خودکار مدیر ارشد فعال می‌ماند.

## ۱۲. پرداخت، پیامک و تنظیمات محیطی

| متغیر | توضیح |
|---|---|
| `JWT_SECRET` | کلید امضای توکن ورود؛ **حتماً** یک رشته تصادفی بلند |
| `DB_NAME`، `DB_USERNAME`، `DB_PASSWORD` | پایگاه داده |
| `SMS_PROVIDER`، `KAVENEGAR_API_KEY`، `KAVENEGAR_OTP_TEMPLATE`، `KAVENEGAR_SENDER` | پیامک کاوه‌نگار؛ بدون کلید، کد ثابت `1111` |
| `PAYMENT_MODE` | `dev` = درگاه آزمایشی (فقط محیط توسعه)، `none` = بدون درگاه تا اتصال درگاه واقعی |
| `PUBLIC_API_URL` | آدرس API از دید مرورگر (در فرانت‌ها قرار می‌گیرد) |
| `PUBLIC_USER_SITE_URL` | آدرس سایت کاربر؛ لینک «مشاهده در سایت» پنل و بازگشت از درگاه |
| `CHECKOUT_HOLD_MINUTES` | مدت نگهداری صندلی (پیش‌فرض ۱۰ دقیقه)؛ سفارش پرداخت‌نشده پس از آن لغو می‌شود |
| `DEMO_SEED_*` | داده نمایشی — بخش ۴ |
| `BACKEND_PORT`، `ADMIN_PORT`، `USER_PORT` | پورت‌ها |

**درگاه آزمایشی:** با `PAYMENT_MODE=dev` (فقط پروفایل توسعه) یک صفحه بانک شبیه‌سازی‌شده باز می‌شود که می‌توانید پرداخت را موفق یا ناموفق کنید. برای درگاه واقعی، کلاسی که `PaymentGateway` را پیاده‌سازی می‌کند در `service/payment` اضافه می‌شود.

## ۱۳. صفحه ۴۰۴ و جلوگیری از لینک خراب

- **صفحه رویداد یا صفحه محتوایی که وجود ندارد** صفحه ۴۰۴ طراحی‌شده را **داخل همان هدر و فوتر سایت** نشان می‌دهد (فایل `frontend/user/src/app/(site)/not-found.tsx`).
- **آدرسی که اصلاً مسیر ندارد** (مثل `/a/b/c`) صفحه ۴۰۴ ریشه را با هدر و فوتر خودش نشان می‌دهد (`frontend/user/src/app/not-found.tsx`).
- هر دو از یک محتوای مشترک (`components/feedback/NotFoundContent.tsx`) استفاده می‌کنند، پس هدر و فوتر هرگز دوبار روی هم نمی‌افتند.
- **بنرهای** متصل به رویداد همیشه به نامک فعلی رویداد لینک می‌شوند؛ اگر نامک رویداد را عوض کنید بنر خراب نمی‌شود. بنری که به رویداد حذف‌شده یا منتشرنشده اشاره کند، در سایت نمایش داده نمی‌شود.
- در پنل مدیریت هم آدرس ناشناخته صفحه ۴۰۴ طراحی‌شده پنل را با دکمه بازگشت به داشبورد نشان می‌دهد.

> **نکته برای مدیران:** نامک رویداد بخشی از آدرس است. اگر آدرس رویداد را جایی منتشر کرده‌اید (پیامک، شبکه اجتماعی)، نامک را تغییر ندهید.

## ۱۴. ریسپانسیو، تم تیره/روشن و PWA

- همه صفحات **راست‌چین** با فونت ایران‌سنس و اعداد فارسی‌اند.
- **ریسپانسیو**: همه صفحات پنل و سایت در عرض‌های ۳۶۰ و ۳۹۰ پیکسل (گوشی) بدون اسکرول افقی صفحه بررسی شده‌اند. جدول‌ها روی موبایل به کارت تبدیل می‌شوند، فیلترها زیر هم قرار می‌گیرند، منوی پنل کشویی است و جدول تقویم و نقشه صندلی داخل کادر خودشان اسکرول/بزرگ‌نمایی می‌شوند.
- **تم**: دکمه ☀/☾ در هدر؛ انتخاب کاربر ذخیره می‌شود و پیش‌فرض، تم سیستم‌عامل است.
- **PWA**: هر دو برنامه قابل نصب روی گوشی هستند و در نبود اینترنت صفحه «اتصال برقرار نیست» نمایش می‌دهند.

## ۱۵. عیب‌یابی و پرسش‌های رایج

**صفحه‌های سایت خالی‌اند.**
لاگ بک‌اند را ببینید (`docker compose logs backend | grep DemoDataSeeder`). اگر نوشته «Database already has its own events, orders or customers» یعنی پایگاه داده داده واقعی دارد و دمو برای حفاظت از آن اجرا نشده؛ برای جایگزینی با دمو از `DEMO_SEED_FORCE=true` (بخش ۴) استفاده کنید.

**صفحه رویداد ۴۰۴ می‌دهد.**
- رویداد در وضعیت «منتشرشده» یا «لغوشده» باشد (پیش‌نویس در سایت دیده نمی‌شود).
- نامک را دقیقاً مطابق آدرس بنویسید (حروف کوچک انگلیسی و خط تیره).

**کد ورود نمی‌آید.**
بدون `KAVENEGAR_API_KEY` پیامکی ارسال نمی‌شود و کد `1111` است. با کلید، قالب `KAVENEGAR_OTP_TEMPLATE` باید در پنل کاوه‌نگار تأیید شده باشد.

**«این شماره تلفن دسترسی به پنل مدیریت ندارد».**
فقط کاربرانی که نوع «مدیر» و حداقل یک نقش دارند وارد پنل می‌شوند (بخش ۱۱).

**بعد از تغییر IP سرور، فرانت به API وصل نمی‌شود.**
`PUBLIC_API_URL` را در `.env` اصلاح و `docker compose up -d --build` را دوباره اجرا کنید.

**تصاویر آپلودشده بعد از ری‌استارت پاک شدند.**
تصاویر در volume داکری `uploads` نگه داشته می‌شوند؛ با `docker compose down -v` این volume هم پاک می‌شود. از `-v` فقط وقتی استفاده کنید که می‌خواهید همه داده‌ها را پاک کنید.

**سفارش «در انتظار پرداخت» خودبه‌خود لغو شد.**
طبیعی است: سفارش پرداخت‌نشده پس از مدت نگهداری (`CHECKOUT_HOLD_MINUTES`) لغو و صندلی‌ها آزاد می‌شوند.

## ۱۶. پیوست: ساختار کد برای توسعه‌دهندگان

### بک‌اند (`src/main/kotlin/com/devs/nisha`)

| پوشه | محتوا |
|---|---|
| `config/` | `MainAdminSeeder` (مدیر ارشد)، `DemoDataSeeder` (داده نمایشی)، `DatabaseAutoCreator`، `WebConfig` |
| `controller/` | API عمومی (`/api/v1/public/...`)، احراز هویت (`/api/v1/auth/...`)، کاربر (`/api/v1/user/...`)، پرداخت |
| `controller/admin/` | API پنل (`/api/v1/admin/...`) به تفکیک بخش |
| `service/` | منطق سفارش، پرداخت، نقشه صندلی، پیامک، داشبورد، لاگ فعالیت |
| `security/` | JWT، فیلتر احراز هویت، کنترل دسترسی نقش‌ها |
| `support/` | `JdbcCrud` (کوئری‌ها)، تاریخ شمسی، کدهای امن |
| `resources/db/migration` | ساختار پایگاه داده (Flyway) — تغییر ساختار فقط با فایل جدید `V11__...sql` |

### فرانت‌اندها (`frontend/user` و `frontend/admin`)

| پوشه | محتوا |
|---|---|
| `src/app/` | مسیرها (App Router). سایت کاربر: همه صفحات داخل گروه `(site)` با هدر/فوتر مشترک |
| `src/features/` (user) | هر بخش سایت: events، seats، checkout، payment، tickets، orders، profile، home |
| `src/components/` | اجزای مشترک: layout، ui، feedback، crud (پنل) |
| `src/services/` | فراخوانی API |
| `src/stores/` | وضعیت ورود (zustand) |

### افزودن یک بخش جدید به پنل
1. جدول با فایل migration جدید.
2. کنترلر در `controller/admin` با `permission_code` جدید.
3. آیتم منو در `admin_menu_items` (با migration).
4. صفحه در `frontend/admin/src/app/<path>/page.tsx` — معمولاً با `CrudPage`.
5. دادن دسترسی به نقش‌ها در «نقش‌ها و دسترسی‌ها».

### تست
```bash
./gradlew test                      # تست‌های بک‌اند
cd frontend/user && npm run build   # بررسی تایپ و ساخت سایت کاربر
cd frontend/admin && npm run build  # بررسی تایپ و ساخت پنل
```
